# 长视频分段转录方案（Whisper OOM 修复）

> 状态：✅ 已实施并验证 | 日期：2026-08-31
> 适用：scan-b 视频分析服务（`/root/scan-b/scan`）
> 目标：解决 >40 分钟长视频 Whisper 转录导致内核 OOM（SIGKILL 137）

---

## 一、问题背景

### 硬件约束
| 资源 | 数值 |
|------|------|
| 物理内存 | 3.9 GB |
| Swap | 0（后补 2GB，见下） |
| GPU | 无（CPU-only，4 核） |
| Whisper 模型 | small（int8） |

### 故障现象
- 42:53 的视频（BV1Mrut6HEHC）转录时，Python 进程 `anon-rss` 冲到 **3.05 GB** 触发内核 OOM，进程被 SIGKILL（exit 137），分析中断。
- 原因：Whisper 整段加载长音频，峰值内存与音频时长近似线性增长；small 模型本身 + 长音频特征矩阵直接撞 3.9GB 天花板。

---

## 二、方案设计

### 核心思路
**"切块 → 逐段转录 → 时间戳平移 → 重叠去重"**：把长音频切成 N 个固定时长切片，每段独立转录（同时只在内存中放一段），最后把所有切片的时间戳加上全局偏移拼回完整时间线，并合并切片边界重叠区的重复文本。

### 参数（`src/config.py`，可通过 `.env` 覆盖）
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `whisper_chunk_seconds` | 600 | 音频超过该秒数（10 分钟）触发分段 |
| `whisper_chunk_overlap` | 2.0 | 相邻切片重叠秒数，防止切片边界断句丢字 |

### 内存收益（实测）
| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 42:53 视频峰值 RSS | **3055 MB → OOM** | **1399 MB**（降 54%） |
| 切片数 | 1（整段） | 5（每段 ~10 分钟） |
| 字幕条数 | 中断，无产物 | 779 条（去重后） |
| 时间戳重叠/倒挂 | — | **0 条**（拼接无缝） |
| 临时切片文件 | — | 每段转录完即删，无残留 |

## 三、实现结构（`src/transcriber.py`）

```
transcribe(audio_path, progress_cb)
├─ _probe_duration()          # PyAV 探测音频总时长
├─ duration <= chunk_len ？    # 短音频走原单次路径（不可见）
│    └─ _transcribe_single()  # 原有逻辑，保持不变
└─ 长音频 → 循环切片
     ├─ _cut_audio_chunk()    # PyAV 流式切割 [start, end] → chunk_XXX.m4a
     ├─ _transcribe_single()  # 每段独立转录（含局部进度→全局进度换算）
     ├─ 时间戳 + offset 平移到全局时间线
     └─ 立即删除该切片文件
最后 _dedup_overlaps()         # 合并边界重叠重复
```

### 关键函数
| 函数 | 作用 |
|------|------|
| `_probe_duration(path)` | 用 `av` 读 `stream.duration * stream.time_base` 得秒数；容器无 duration 时回退为解码帧跟踪 max pts |
| `_cut_audio_chunk(src, out, start, end)` | `av` 流式 decode+encode 成 m4a/aac，seek 到 start 后 mux `[start, end]` 内的帧 |
| `_transcribe_single(model, path, cb)` | 原单次转录逻辑抽取，含 VAD、beam_size=1 |
| `_dedup_overlaps(entries, overlap)` | 排序后只对**时间重叠**且**文本近似**的条目去重；非重复的重叠条目钳制 start |
| `_text_similar(a, b)` | bigram 重叠率 ≥0.85 或互相包含 → 判为重复 |

### 进度回调
每段内 `_transcribe_single` 报 0-100%，换算为全局：`(段起始时间 + 段内百分比×段时长) / 总时长 × 100`。

## 四、PyAV 踩坑记录（每个都花了一次调试周期）

1. **`ctx.layout.name` 是垃圾值** — `av.AudioLayout('1 channels').name` 返回字符串 `"1 channels"`，不是合法 layout 名，设置到输出流会让 `avcodec_open2("aac", {})` 返回 error 22。**正确做法**：按声道数映射合法名：`1→"mono"`、`2→"stereo"`。
2. **`container.seek()` 用的是流 time_base 单位，不是微秒** — 正确写法 `in_c.seek(int(start / float(in_s.time_base)), stream=in_s, backward=True)`。用 `start * 1_000_000` 会定位错误。
3. **WAV 的 `stream.duration` 可能为 None/0** — 必须保留"解码帧跟踪 max pts"的回退分支。
4. **编码器要 flush** — 循环结束后必须 `out_s.encode(None)` 冲掉编码器缓冲帧，否则每个切片尾部会被静默丢弃。
5. **aac 编码器存在但挑剔** — 本环境 av 自带 aac，但只在 layout 合法时能 open；保留 `mp3` 兜底（try/except）。

## 五、去重精度（测试中发现的两个 bug）

1. **偏移阶段绝不能跳过条目** — 初版写 `if e.end < offset: continue`，但 `e.end` 是**局部时间**（0~chunk_len）而 `offset` 是**全局偏移**，单位不匹配：第二个切片起所有条目都被跳过，以未偏移的局部时间加入，去重时几乎全被误删。**修复**：偏移阶段所有条目一律 `+offset`，重叠交给 `_dedup_overlaps` 处理。
2. **只对时间重叠的条目做相似度判定** — 初版全局按文本相似度去重（阈值 0.6），`内容0060` vs `内容0061` 共享 4/5 bigram（0.8≥0.6）被误判重复，连锁删光。**修复**：相似度检查必须满足 `e.start < last_kept.end - 0.01`（时间重叠），且阈值提到 **0.85**（真实 Whisper 重复是近完全相同的字符串；不同句子不会 85% bigram 重叠）。

## 六、验证方法（可复现）

### 1. 纯切割单元测试（`_cut_test.py`）
生成 65s 正弦 WAV → 切 `[0,60]` + `[58,65]`（2s 重叠）→ 断言两段时长 ≈60s / ≈7s。

### 2. 分段流程测试（`_chunk_test.py`，无需真实模型）
- 生成 ~21 分钟正弦 WAV（1300s）
- monkeypatch `T._get_model` 返回 FakeModel，其 segment 文本按**全局时间**生成（解析 `chunk_<i>.m4a` 文件名 → `global_offset=(i-1)*chunk_len`），使重叠区产生相同文本、非重叠区不同
- 断言：模型被调用 N 次、时间线覆盖全时长、每个全局 marker 恰出现一次、0 时间戳重叠、去重仅删少量边界重复、无残留切片文件

### 3. 短音频回归（`_short_test.py`）
65s WAV → 断言模型只被调用 1 次（单次路径不受影响）、无切片文件。

### 4. 生产端到端
- 提交之前 OOM 的 BV id：`POST /api/analyze?url=...`
- 后台轮询 `/proc/<pid>/status` 的 VmRSS + grep 服务日志 `Long audio (...)` / `Chunk i/N done: M entries`
- 校验最终 `subtitles.srt` 时间戳单调递增、末条接近视频总时长

## 七、相关辅助配置

### 2GB swap（安全网，与分段配合）
```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
# /etc/fstab 追加：/swapfile none swap sw 0 0
```
分段后峰值 ~1.4GB，2GB swap 覆盖了峰值与物理内存的缺口，双保险。

### 待办 / 可选优化
- Whisper small → base 可进一步降内存（精度略降）
- 分段数可调 `whisper_chunk_seconds`（5/15 分钟皆可，10 分钟为当前平衡点）
- 建议避免 Whisper 与 RAG（bge-m3）并行，两者叠加仍有触顶风险
