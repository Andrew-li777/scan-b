# 未来发展 — 实体软件定位、核心竞争力与演进路径

## 一、为什么是实体软件而非线上网站

### 1.1 核心矛盾

项目的最强功能（免费 GPU 转录）和线上部署互相矛盾，强行 SaaS 化会同时失去成本优势和功能完整性。

```
                   本地 (实体软件)          线上 (SaaS)
                   ──────────────          ────────────
Whisper 转录       GPU 本地跑，零边际成本     GPU 实例 $0.5-2/h × 用户数
字幕提取           yt-dlp 住宅 IP 可过      数据中心 IP 被 YouTube/Bilibili 封
API Key           本地 .env 从不离开电脑      必须管理用户密钥池、加密存储
隐私               全硬盘落地，0 泄露面        服务器存储用户观看记录 = 法律风险
Obsidian 集成      直接写本地 Vault           线上无法触达用户文件系统
反爬对抗 (412)     cookie + 住宅 IP           数据中心 IP + 无 cookie = 瞬封
```

**结论**：线上化 = 砍掉 Whisper（最值钱的部分）+ 引入服务器成本 + 背上合规风险。

### 1.2 适合做线上的部分

| 组件 | 当前 | 线上可行性 |
|------|------|:--:|
| LLM 分析 (摘要/重点/概念) | DeepSeek API | ✅ 天然线上，已在用 |
| ChromaDB 向量检索 | 本地 | ❌ 数据在本地 |
| 字幕提取 | yt-dlp + Whisper | ❌ 反爬封 IP |
| Web UI | FastAPI localhost | ✅ 可复用 |
| Obsidian 输出 | 文件系统 | ❌ 无法触达本地 |

## 二、核心竞争力

### 2.1 技术壁垒

| 能力 | 壁垒来源 | 商业替代品不能做 |
|------|----------|-----------------|
| **GPU 转录** | 用户自有显卡 + CTranslate2 量化 | Eightify/Glarity 用 API 计费，不可能免费 |
| **Bilibili 412 对抗** | UA 轮换 + WBI 签名 + cookie 注入 + playurl API 直连 | 商业产品无动力维护反爬链 |
| **Obsidian 原生集成** | YAML frontmatter + `[[wikilink]]` + Vault 直写 | 线上服务碰不到本地文件系统 |
| **隐私闭环** | API Key + 字幕 + 分析结果全在本地 | SaaS 数据天然在服务器 |
| **离线可用** | ChromaDB + diskcache 持久化 | 线上断网即不可用 |

### 2.2 差异化定位

```
市场竞争格局:

Eightify / Glarity       ── 浏览器插件，YouTube 摘要，付费订阅
Notta / Otter.ai         ── 会议转录，SaaS，按月收费
Descript                 ── 视频编辑 + 转录，SaaS
Language Reactor         ── 语言学习，双字幕

本项目:
  1. 全平台 (YouTube + Bilibili) ── 竞品只做 YouTube
  2. GPU 本地转录 ── 竞品按 token/分钟计费
  3. Obsidian 知识库集成 ── 竞品输出独立平台
  4. RAG 问答 ── 竞品是单向摘要
  5. 免费 ── 唯一成本是 DeepSeek API (几百 token/视频)
```

| | Electron | Tauri | Pake (Rust打包) |
|------|:--:|:--:|:--:|

| Python 后端 | ✅ subprocess | ✅ sidecar | ❌ 仅前端 |
| Chromium 内置 | ✅ | ❌ 需系统 WebView | ❌ 仅前端 |
| 开发周期 | 2 天 | 5 天 | — |
| 跨平台 | Win/Mac/Linux | Win/Mac/Linux | Win/Mac/Linux |
| **推荐** | ⭐⭐⭐ | ⭐⭐ | ❌ |

**Electron 方案技术细节**：

```
目录结构:
  video-analyzer-desktop/
  ├── package.json
  ├── main.js              # Electron 主进程
  ├── preload.js           # 安全隔离
  ├── assets/
  │   └── icon.png
  └── backend/             # Python 后端 (git submodule)
      └── (现有 scan 项目)

main.js 核心逻辑:
  1. app.on('ready') → spawn python -c "import uvicorn; ..."
  2. 等待 http://127.0.0.1:8787 就绪 (轮询)
  3. 创建 BrowserWindow → loadURL('http://127.0.0.1:8787')
  4. 系统托盘: 右键菜单 (显示窗口 / 退出)
  5. app.on('window-all-closed') → kill python 子进程

打包:
  electron-builder → .exe/.dmg/.AppImage
  Python 环境仍需用户安装 (或捆绑 embedded Python ~30 MB)
```

**打包为独立 exe**：

```
方案 A (轻量): Electron 壳 + 提示用户安装 Python + pip install -r requirements.txt
方案 B (完整): Electron 壳 + embedded Python + 所有 pip 包预装
  - embedded Python: 30 MB
  - pip 包 (torch + chromadb + faster_whisper + ...): ~3 GB
  - 安装包大小: ~1.5 GB (7z 压缩)
  - 劣势: 超大，更新不便
方案 C (推荐): Electron 壳 + 首次启动引导安装
  - 内置 requirements.txt
  - 首次启动检测 pip → 自动安装依赖 → 进度条
  - 安装包 ~200 MB，依赖按需下载
```

### 路线 C：NAS / 局域网部署 (1-2 天)

```
目标: 家里一台机器跑服务，其他设备通过局域网访问

改动:
  1. host: "127.0.0.1" → host: "0.0.0.0"
  2. 前端加 CORS (如需)
  3. 配置 ARP 绑定或 DHCP 固定 IP
  4. 可选: systemd (Linux) 或 nssm (Windows) 注册为服务

使用场景:
  - 台式机 GPU 跑服务 → 笔记本/手机浏览器访问
  - 挂 NAS 上 → 24×7 运行，全家共享
  - 树莓派 + USB 外接 GPU 不可行 (无 CUDA)

注意事项:
  - API Key 安全性: 局域网内的设备可调用 DeepSeek Key → 建议加简单 token
  - GPU 独占: 同时只能跑一个转录任务 (并发需排队)
```

## 五、Electron 桌面应用 — 详细技术方案

### 5.1 项目初始化

```bash
mkdir video-analyzer-desktop
cd video-analyzer-desktop
npm init -y
npm install electron electron-builder
npm install wait-on  # 轮询后端是否就绪
```

### 5.2 main.js 核心逻辑

```javascript
const { app, BrowserWindow, Tray, Menu, nativeImage } = require('electron');
const { spawn } = require('child_process');
const path = require('path');

let mainWindow, tray, backendProcess;

const BACKEND_PORT = 8787;
const BACKEND_URL = `http://127.0.0.1:${BACKEND_PORT}`;

function startBackend() {
  const pythonCmd = process.platform === 'win32' ? 'python' : 'python3';
  const code = `import uvicorn; uvicorn.run('src.web.server:app', host='127.0.0.1', port=${BACKEND_PORT})`;
  
  backendProcess = spawn(pythonCmd, ['-c', code], {
    cwd: path.join(__dirname, 'backend'),  // scan 项目目录
    stdio: 'pipe'
  });
  
  backendProcess.stderr.on('data', (d) => console.log('[backend]', d.toString()));
  
  return new Promise((resolve) => {
    // 轮询直到后端就绪
    const http = require('http');
    const check = () => {
      http.get(BACKEND_URL, (res) => {
        if (res.statusCode === 200) resolve();
        else setTimeout(check, 500);
      }).on('error', () => setTimeout(check, 500));
    };
    check();
  });
}

async function createWindow() {
  await startBackend();
  
  mainWindow = new BrowserWindow({
    width: 1200, height: 800,
    title: 'Video Analyzer',
    webPreferences: { nodeIntegration: false, contextIsolation: true }
  });
  
  mainWindow.loadURL(BACKEND_URL);
  
  // 最小化到托盘而非关闭
  mainWindow.on('close', (e) => {
    if (!app.isQuitting) {
      e.preventDefault();
      mainWindow.hide();
    }
  });
}

app.whenReady().then(() => {
  // 系统托盘
  tray = new Tray(nativeImage.createEmpty());
  tray.setToolTip('Video Analyzer');
  tray.setContextMenu(Menu.buildFromTemplate([
    { label: '显示窗口', click: () => mainWindow.show() },
    { label: '退出', click: () => { app.isQuitting = true; app.quit(); } }
  ]));
  
  createWindow();
});

app.on('before-quit', () => {
  if (backendProcess) backendProcess.kill();
});
```
